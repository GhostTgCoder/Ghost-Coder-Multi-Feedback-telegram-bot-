# Архитектура на высоком уровне

Эта схема описывает роли компонентов по структуре переданного архива, а не гарантирует отсутствие ошибок в конкретной сборке.

- **Telegram Bot API / aiogram** — получение сообщений, callback-запросы и отправка ответов.
- **Модуль приложения** — маршрутизация сообщений, темы обращений, рабочие часы, автоназначение и фоновые задачи.
- **Административный интерфейс Telegram** — настройки ботов, операторов, пользователей, сообщений, шаблонов, статистики и отдельных параметров диалога.
- **Менеджер данных** — чтение и запись локальных файлов конфигурации и состояния.
- **Модуль публикаций** — планирование, публикация, редактирование и удаление публикаций, если это разрешено Telegram.
- **Модуль групповой модерации** — проверки на флуд, повторяющиеся сообщения, ссылки и запрещённые слова в пределах активных правил.

## Данные и хранение

Исходная версия использует локальные JSON-файлы для конфигурации и части данных. Это означает, что целостность файлов, права доступа, резервное копирование и корректное поведение при одновременной записи особенно важны. Перед эксплуатацией на нескольких процессах проверьте, поддерживает ли конкретная версия выбранный режим запуска.

## Рекомендуемый контур

`Пользователь → Telegram Bot API → бот поддержки → тема в форумной группе → ответ оператора → пользователь`

Для нескольких клиентов/брендов используйте отдельные токены, раздельные настройки и минимально необходимые права доступа.
